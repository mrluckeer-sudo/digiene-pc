## Стек и архитектура

- Обычный HTML, CSS и JS, без сборки, без `package.json`, без npm.
- Файлы: `index.html`, `css/desktop.css`, `js/desktop.js`, `js/onboard.js`, `js/workplace.js` (~2300 строк JS, ~900 строк CSS).
- Состояние в `sessionStorage`, ключ `nord-desktop-v2`.
- Локально: из папки проекта `python3 -m http.server 8820`, если сервер уже слушает — второй не поднимать. В `index.html` у css и js стоит `?v=14`; при правках номер поднимать.
- **Рекомендация по React (согласовано в обсуждении):** переход на React сейчас не нужен. Текущий объём управляем; фреймворк имеет смысл при росте кода/команды. Для адаптива достаточно CSS. Подробности — в `docs/portal-proposals.md`, раздел «Технологический стек».

## Что уже работает

- Онбординг «Первый рабочий день» с «Пропустить онбординг». Экран приложений — короткие описания (зачем сотруднику и зачем в учебном дне), без слов про атаки. После завершения или пропуска справа снизу всплывает плашка Миши из «Сообщений», даже если онбординг пропустили. Почта сама не открывается.
- Почта: написать, черновики, входящие, отправленные, спам, удалённые, контакты с отчествами, ответ, ответ всем, пересылка, карточка вложения со «Скачать». Кнопок «Оплатить по письму», «Открыть разбор» и «Спросить у ассистента» нет.
- Файлы выглядят как Finder: боковая панель, колонки, предпросмотр; создать папку, переименовать, переместить, удалить; скачивание вложения из почты на диск; приложить файл из диска к письму.
- Портал, раздел «Оплата контрагентам»: «Загрузить счёт» открывает диск, выбранный файл проводится кнопкой «Оплатить», ниже журнал прошлых оплат. Известный файл УЧ-1042 становится ООО «Северный контур», 186 400, «Проведено». Повтор того же счёта пишет «Этот счёт уже проведён» и вторую строку не добавляет.
- Онбординг оплаты. При первом открытии письма со счётом — плашка «Как оплачивать счета?». По нажатию подсказки обводят кнопки и не блокируют клики. Дальше шаг идёт только после удачного действия: скачать и сохранить файл на компьютер, открыть «Портал», загрузить файл с диска, нажать «Оплатить». На подсказке есть «Пропустить».
- Прочие плашки тоже справа снизу: появляются и сами гаснут, клик открывает нужное приложение.
- Календарь: день, неделя и месяц, свои события, гости из справочника, входящие приглашения и напоминания плашкой. Полное задание — `docs/КАЛЕНДАРЬ.md`.

## Пробелы в почте и Finder (зафиксировано при разборе кода)

Не реализовывать автоматически — только как задел:

- Почта: нет drag & drop писем на папки; нет «пометить непрочитанным»; нет поиска; нет кнопки «вернуть во входящие» из спама/корзины; нет универсального журнала всех действий (есть только `ledger` для сценария директора).
- Finder: функция `copyNode` есть, но пункта «Копировать» в меню нет; нет «Отправить почтой» из контекстного меню; нет drag & drop файлов; нет поиска.
- Для будущего журнала удобная заглушка: `logEvent(action, data)` в `state.eventLog`.

## Предложения и идеи (не кодить без просьбы)

Полный текст — в `docs/portal-proposals.md`. Кратко:

1. **Портал по ролям** — модули для финансиста, IT и общие (новости, рассылка, справочник, календарь мероприятий, заявления).
2. **Общий диск** — клиенты, договоры, прайсы, отчёты, поставщики, папка «Конфиденциально»; мотивация защищать данные.
3. **Браузер** — идея: мега-ограниченный, без своей поисковой и без кучи заготовок; только сценарные сайты по ссылкам; проверка домена.
4. **Мессенджер** — краткие идеи после звонка: группы, файлы/ссылки, фишинг от «коллеги», просьбы кода.
5. **Календарь** — задание на разработку вынесено в `docs/КАЛЕНДАРЬ.md` и уже собрано в приложении. В предложениях остаётся только сюжетная идея фишингового приглашения.
6. **Адаптивность** — с телефона ломается (с телефона и не должно работать), но нужны корректные размеры окон и сетка для очень высоких и очень низких разрешений десктопа.
7. **Стек** — вопрос про React; рекомендация: оставаться на чистом JS.

В конце `portal-proposals.md` — дословные пожелания пользователя (требуют уточнения): «задачи на какие-нибудь рецепты», «какие новости там должны быть», «шаблоны какие-то сделать», «какие изображения сгенерировать».

## Чего не делать, пока не попросят

Пять учебных сценариев, скины ролей, публичную Cloud Function, ключ в сайте или в git. Роли в настройках сохраняются, но содержимое от них не меняется. Предложения из `portal-proposals.md` тоже не реализовывать без явной просьбы.
