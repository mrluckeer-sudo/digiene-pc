## 1. Портал: роли через онбординг

Сейчас Портал выглядит одинаково для всех. Предложение — сделать его набором модулей, которые подбираются под роль игрока. Роль выбирается при онбординге и определяет, какие разделы доступны.

### Финансист

Роль сотрудника, который работает со счетами, платежами и бюджетами.

Доступные модули:
- Реестр счетов на оплату — входящие счета от контрагентов, статусы согласования
- Оплата контрагентам — загрузка счёта, проведение платежа (уже частично реализовано)
- История платежей — журнал проведённых операций с фильтрами по дате, контрагенту, сумме
- Уведомления о просрочке — напоминания о неоплаченных счетах и приближающихся сроках

### IT-специалист

Роль сотрудника технической поддержки или системного администратора.

Доступные модули:
- Заявки на доступ — запросы от сотрудников на доступ к системам, согласование и выдача прав
- Установка ПО — каталог разрешённого программного обеспечения, заявки на установку
- Тикеты в поддержку — обращения пользователей, статусы решения, история переписки
- Журнал инцидентов — записи о сбоях, инцидентах безопасности, проведённых работах

### Общие модули для всех ролей

Независимо от выбранной роли, каждый сотрудник видит:
- Внутренние новости — объявления компании, изменения в политиках, важные даты
- Корпоративная рассылка — дайджест событий, поздравления, достижения команд
- Справочник сотрудников — ФИО, должность, отдел, контактный email и телефон
- Календарь мероприятий — собрания, тренинги, корпоративные события
- Модуль «Заявления» — подача заявлений на отпуск, командировку, больничный, отгул

## 2. Портал: общий диск с корпоративными данными

Раздел Портала или отдельное приложение, дающее доступ к корпоративным файлам и базам данных. Эти данные имеют коммерческую ценность — их утечка создаёт реальный ущерб для компании.

### Содержимое корпоративного диска

- **База клиентов** — названия компаний, контактные лица, телефоны, email, история сделок и переговоров
- **Шаблоны договоров** — типовые формы с ценами, условиями поставки, реквизитами компании
- **Внутренние прайсы** — тарифные сетки, скидочные условия, себестоимость товаров и услуг
- **Отчёты по выручке** — финансовые сводки, показатели продаж, планы и факты
- **Списки поставщиков** — контакты, договорные ставки, условия работы, рейтинги надёжности
- **Папка «Конфиденциально»** — служебные доступы, пароли от серверов, ключи API внешних сервисов

### Почему это важно для игровых сценариев

Данные корпоративного диска коммерчески значимы. Если злоумышленник получает к ним доступ, он может:

**Продать конкурентам.** Клиентская база с историей сделок, внутренние прайсы и условия поставщиков — ценный товар на чёрном рынке. Конкурент узнаёт, с кем работает компания, по каким ценам, и может переманить клиентов или выторговать лучшие условия у тех же поставщиков.

**Использовать для фишинга.** Имея шаблоны договоров, реквизиты и стиль переписки компании, злоумышленник может создать убедительные поддельные письма. Клиенты получают «счёт» с правильным оформлением, но с подменёнными реквизитами — и переводят деньги мошенникам.

**Получить доступ к системам.** Пароли и ключи API из папки «Конфиденциально» открывают прямой путь к внутренним сервисам. Злоумышленник может войти в CRM, бухгалтерию, почтовый сервер — и действовать от имени компании.

**Шантажировать компанию.** Угроза публикации клиентской базы, финансовых отчётов или конфиденциальных данных — повод для вымогательства. Компания рискует репутацией, штрафами за утечку персональных данных, потерей доверия клиентов.

### Игровая мотивация

Понимание ценности данных создаёт для игрока мотивацию:
- Не открывать файлы по сомнительным ссылкам из писем
- Не выгружать данные на внешние сервисы без проверки
- Сообщать о подозрительных запросах на доступ к базам
- Проверять, кому и зачем передаёт корпоративные документы

## 3. Браузер

> Идея на обсуждение, не обязательная задача.

- Браузер должен быть **мега-ограниченным** — реальные существующие сайты открывать не получится, и это нормально
- Делать свою поисковую систему — странно
- Делать кучу заготовок разных сайтов — тоже странно
- Браузер нужен **для сценариев**: конкретные фишинговые или рабочие сайты, которые открываются по ссылкам из почты или мессенджера
- Игрок взаимодействует с этими сайтами в рамках сюжета
- Есть корпоративный сайт компании, на котором оказываются какие-то услуги
- Сотрудник должен понимать, какой домен он видит, отличать `nord.example` от `n0rd.example`
- Пока просто идея — не факт, что будем делать

> Краткие идеи; полное ТЗ обсуждалось отдельно.

## Связь с компетенциями

Предложения поддерживают компетенции из документа `kekodemy-b2b-competencies-digiene-2026-11-20.md`:

- **Обращаться с рабочими данными в пределах разрешённого доступа** — проверка получателя, выбор места для файла, ограничение лишнего доступа
- **Проверять рабочие сообщения и запросы перед действием** — распознавание фишинга под видом легитимных запросов на выгрузку данных

## 6. Адаптивность

> Проблема выявлена при проверке.

Игра браузерная, у пользователей разные экраны и разрешения. Важно:
- Правильные размеры окон приложений при разных разрешениях
- Корректное расположение и местоположение приложений на рабочем столе
- Сетка, которая масштабируется под экран

**Текущее состояние:** проверено с телефона — всё сломано, никакого адаптива, сетки нет.

**Уточнение:** с телефона в целом работать не должно (это эмулятор десктопа), но нужен заложенный адаптив для:
- Очень высоких разрешений (4K, Retina)
- Очень низких разрешений (старые мониторы, небольшие ноутбуки)
- Разных соотношений сторон

## 7. Технологический стек

> Вопрос на обсуждение.

Стоит ли думать о переходе на React или другие фреймворки, или текущий стек технологий нормален?

**Текущий стек:**
- Чистый HTML + CSS + JS
- Без сборки, без npm
- Состояние в sessionStorage
- Локальный запуск через `python3 -m http.server`

**Аргументы за текущий стек:**
- Простота деплоя (статика в бакет)
- Нет зависимостей, нет node_modules
- Быстрый старт разработки

**Аргументы за фреймворк:**
- Компонентный подход упрощает поддержку при росте
- Реактивность состояния из коробки
- Инструменты разработчика
